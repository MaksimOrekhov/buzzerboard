# BuzzerBoard

NBA-хаб: матчи, результаты, таблицы, новости, статистика и аналитика.

Матчи и турнирные таблицы работают с реальными данными через Worker и общий D1-кеш. Все разделы используют единую тёмную дизайн-систему: Manrope, голубой акцент, Reka UI и адаптивные таблицы. Новости пока не подключены; интерфейс честно показывает доступность и время загрузки данных. Обновление источника по умолчанию выключено.

## Требования

- Node.js `22.12` или новее
- pnpm `10.28.0` (через Corepack или [официальную установку](https://pnpm.io/installation))

## Начало работы

```sh
pnpm install --frozen-lockfile
pnpm run dev
```

## Структура

- `src/app` — точка входа, оболочка, маршруты и клиент TanStack Vue Query.
- `src/pages` — страницы «Главная», «Матчи», «Турнирная таблица», «Новости» и «Избранное».
- `src/shared/components` — небольшие общие компоненты интерфейса.
- `src/assets` — общие токены, базовые стили и оболочка; стили функций находятся в `src/features`.
- [docs/design-system-v2-pro186.md](docs/design-system-v2-pro186.md) — компоненты дизайн-системы, лицензии, правила расширения и визуальные проверки.
- `.github/workflows/ci.yml` — проверки pull request и push в `main`.

Результаты проверки DunkAPI, расход кредитов и модель NBA/Europe/Nicosia описаны в [docs/dunkapi-spike.md](docs/dunkapi-spike.md). Сетевой smoke-прогон запускается вручную и не входит в CI или unit tests.

Доменные модели, граница server-only адаптеров, внутренние контракты API и правила нормализации описаны в [docs/nba-data-contracts.md](docs/nba-data-contracts.md).

Cloudflare Worker, общий D1-кеш, обновление по Cron и ручной защищённый revalidation описаны в [docs/backend-runtime.md](docs/backend-runtime.md). Provider refresh по умолчанию выключен.

Каждый сетевой запуск smoke-скрипта отдельно расходует до 18 кредитов (основной режим) или 9 (ID cross-check). Скрипт ограничивает расход только на один запуск и не хранит историю уже списанных кредитов или остаток аккаунта. Перед повторным запуском проверьте бюджет вручную; для сетевого запроса нужно явно подтвердить его лимит: `pnpm run dunkapi:smoke -- --execute --confirm-credit-spend=18` или `pnpm run dunkapi:smoke -- --verify-identifiers --execute --confirm-credit-spend=9`. Не запускайте повторно завершённую проверку PRO-163 с тем же ключом без отдельного бюджета.

Для визуальных проверок всех разделов используйте `pnpm visual:pro186` (только синтетические ответы, без upstream). Для локального просмотра данных запустите `pnpm worker:dev` с отключённым refresh и `pnpm dev`; Vite проксирует `/api` на локальный Worker.

Состоянием запросов управляет TanStack Vue Query. Pinia не добавлена: общего клиентского состояния пока нет. Локальные настройки храните в `.env.local` (файл игнорируется git). Переменные с префиксом `VITE_` попадают в клиентскую сборку и не должны содержать секреты.
