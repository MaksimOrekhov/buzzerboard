# PRO-195 · Игроки NBA (BBS)

## Покрытие

На 18 ноября 2026 года четыре страницы [сезонного каталога BBS](https://api.bigballsdata.com/openapi.json) (`/v1/stored/players?league=nba&season=2026`, до 200 строк на страницу) дали **645 уникальных NBA UUID из 645 строк**, по всем 30 каноническим командам. Это знаменатель каталога, привязанного к клубам сезона; он не подтверждает актуальный состав. Лидерборд возвращает одну выбранную метрику и до 50 записей. Пакетный эндпоинт со всеми сезонными средними в OpenAPI не найден.

| Проверка                                                | Результат |
| ------------------------------------------------------- | --------: |
| Проверено сезонных эндпоинтов и доступно стабильных URL |       645 |
| Совпадающая строка со сыгранными матчами и средними     |       468 |
| Без подтверждённых средних                              |       177 |
| Неоднозначные множественные строки сезона               |         0 |
| Загружены паспорт профиля и журнал                      |        10 |
| Есть хотя бы строка журнала или сохранённого box score  |       332 |
| Подтверждённых ссылок из журналов на матчи              |       381 |
| Совпавших UUID у лидеров команд                         |       149 |

У 468 строк заполнены все 20 показателей. GP — количество матчей, остальные объёмы — средние за игру. MIN из MM:SS переведены в десятичные минуты, процент хранится как доля. Строки разных команд не объединяются; сезон 2026 у провайдера означает 2026/27. Значения из профиля и сезонных средних у одного игрока различались: для средних используется только специализированный эндпоинт.

Десять расширенных примеров охватывают десять команд; три игрока имеют не более семи матчей. Три текущие команды в профиле отличаются от команды в каталоге. Обе показаны с отдельными подписями; причина отличия не выводится. Журнал до 15 игр дополняется только строками с тем же BBS UUID и датой из локального box score. Пересечение по дате и сопернику не дублируется. Ссылки на матч доступны только для подтверждённых строк. Несопоставленные идентификаторы остаются текстом; имена для склейки не используются. Кеш не считается полным журналом сезона. Фотографии не показываются, расширенные метрики не заявлены.

## Бюджет и обновление

Один публичный OpenAPI GET и **681 авторизованный BBS GET**: 6 диагностических, 665 в основном проходе (включая один HTTP 503), 6 для двух дополнительных профилей и 4 при возобновлении. Повторный проход пропустил 642 сохранённых средних и загрузил три оставшихся. Ключ Free сообщил 2000/день и 100/мин. Ручной локальный сбор ограничен 850 GET за проход, интервалом 1050 мс и остановкой при низком X-RateLimit-Remaining или ошибке провайдера. Учитывайте Retry-After и расход других клиентов ключа, запускайте один сбор за раз. Прогресс хранится в отдельных закрытых файлах. Для дозагрузки профиля используйте `--profile UUID`, для свежего сезонного снимка — новый каталог.

`GET /api/players` и `GET /api/players/:id` читают по одному ограниченному сезонному снимку из D1. Каталог фильтруется и сортируется в браузере, по 25 строк на страницу. Снимок старше 24 часов помечается как устаревший. Миграция 0006 добавляет отдельную таблицу. Импорт атомарный; исходные кеши не меняются. Обновление не входит в Worker, CI или Cron. Чтобы отключить API игроков, уберите локальный флаг BBS_PLAYERS_ENABLED.

## Запуск с данными

В этой рабочей копии заполненный D1 находится в `.wrangler/pro195`: скопированы существующие матчи и команды, затем импортирован снимок игроков. Исходные базы не менялись.

```sh
pnpm build
XDG_CONFIG_HOME=.wrangler/config WRANGLER_WRITE_LOGS=false WRANGLER_SEND_METRICS=false \
  pnpm exec wrangler dev --ip 127.0.0.1 --port 8795 --persist-to .wrangler/pro195 \
  --var BBS_PLAYERS_ENABLED:true --var NBA_GAMES_PROVIDER_ORDER:bbs \
  --var BBS_REFRESH_ENABLED:false --var DUNKAPI_REFRESH_ENABLED:false \
  --var DUNKAPI_BOX_SCORE_REFRESH_ENABLED:false
```

[Игроки](http://127.0.0.1:8795/players) · [Команды](http://127.0.0.1:8795/teams). Чтобы воссоздать кеш на этой машине, остановите Worker, примените миграции и импортируйте данные:

```sh
XDG_CONFIG_HOME=.wrangler/config WRANGLER_WRITE_LOGS=false WRANGLER_SEND_METRICS=false \
  pnpm exec wrangler d1 migrations apply buzzerboard-nba-cache --local --persist-to .wrangler/pro195
# Укажите файлы данных D1 (не metadata.sqlite) из .wrangler/pro195,
# .wrangler/state и /private/tmp/pro189-wrangler-state соответственно.
node scripts/bbs-players-copy-cache.mjs "$PLAYER_DB" "$GAME_DB" "$TEAM_DB"
node scripts/bbs-players-import.mjs /private/tmp/pro195 "$PLAYER_DB" 2026
```

Сырые ответы в `/private/tmp/pro195`, база в `.wrangler/` и PNG в `artifacts/pro-195/visual/` остаются локально. DunkAPI и production не использовались.
