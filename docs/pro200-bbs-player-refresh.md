# PRO-200: BBS сезонная статистика игроков

## Поведение

Автоматическая очередь игроков использует существующий десятиминутный Worker Cron, общий lock планировщика, BBS request reservation, cooldown и нормализаторы. Она запускается только после завершения доступных задач core-очереди (матчи, box score, команды и standings). Ошибочная запись получает отдельный повтор с задержкой; глобальные ошибки и исчерпание квоты ставят очередь на паузу. Курсор, staging и фаза сохраняются в D1, поэтому очередь продолжается после полуночи и повторного запуска Worker.

Сезонный каталог обновляется страницами по 200 строк раз в семь дней. Перед публикацией проверяются сезон, scope, полнота пагинации, UUID игроков, команды и отсутствие повторов. Записи из неполной или несовместимой выборки не заменяют последний хороший снимок. Средние для игроков запрашиваются по подтверждённым UUID, сохраняются в небольшой staging-таблице и публикуются в снимок группами до 25 наблюдений. Явные нулевые матчи обновляют отметку проверки, но пустой ответ не стирает прежнюю статистику. После цикла недавние связи игрока с матчами сверяются только с уже сохранёнными BBS матчами и box score; дополнительных запросов для них нет. Профиль и журнал матчей постепенно обновляются для одного игрока за завершённый цикл.

Каталог показывает фазу, прогресс, время последнего цикла и дату проверки средних каждого игрока. Сезонные показатели и расширенные поля профиля остаются в версии снимка `v2`; публикация сохраняет существующие данные и использует общий лимит строки D1 в 1.8 MB. Для сверки недавних матчей читаются не более двух дневных списков матчей и box score этих дней (до 32 операций при NBA-календаре). В одной записи worker выполняет одну внешнюю работу очереди; для обогащения отдельного профиля вызываются только профиль и gamelog этого игрока.

## Квота и расписание

Production сохраняет существующие значения: Cron `*/10 * * * *`, общий лимит приложения 150 BBS-запросов в сутки, не более 10 в минуту, request headroom 25 и настроенный интервал между запросами. Новых лимитов и провайдеров не добавлено. Обновление игроков выключено переменной `BBS_PLAYER_REFRESH_ENABLED=false`; основной BBS refresh не меняется. DunkAPI не используется.

При каталоге из 645 игроков полный проход средних требует около 645 запросов, а каталог — ещё четыре запроса страницами по 200. В лимите 150/сутки невозможно завершать такой проход каждый день вместе с приоритетными обновлениями матчей, команд и таблиц. Поэтому cursor проходит весь список постепенно, расходуя только остаток после core-задач и защиты headroom. Фактическая длительность зависит от числа матчей и повторов; отметки обновления показывают реальное покрытие, а незавершённый проход не сбрасывается в полночь. Поле `averageUpdatedAt` не означает, что средние всех 645 игроков свежи за последние сутки.

## Активация

Новая миграция `0008_bbs_player_refresh.sql` создаёт только таблицы состояния и staging. После проверки миграции и явного отдельного решения можно включить Workers variable `BBS_PLAYER_REFRESH_ENABLED=true`. До этого момента worker не делает запросов для игроков и не создаёт player-refresh state. Для отката достаточно вернуть эту переменную в `false`; существующий BBS core Cron продолжает работать.

## Синтетические проверки

Тесты проверяют идентичность игрока и сезона в средних, допустимую пустую выборку для игрока с 0 матчей, дубликаты строк и полноту сезонной пагинации. Внешние BBS/DunkAPI endpoints во время тестов не вызываются.
