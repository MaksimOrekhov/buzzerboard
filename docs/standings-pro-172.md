# Турнирные таблицы NBA (PRO-172)

Экран `/standings` получает `GET /api/standings?seasonEndYear=2027` через TanStack Vue Query. Worker читает общий локальный D1-кеш, не выполняя запросов к DunkAPI. Кнопка обновления повторяет только этот GET. В клиентский код не передаются API-ключи.

## Представление данных

- Восточная и Западная конференции отображаются отдельно. Неполный набор команд показывается с явным количеством; пустой ответ отличим от ошибки `cache_miss`.
- Снимок показывает источник, время `fetchedAt`, часовой пояс пользователя и признак устаревших данных. При ошибке повторного чтения уже загруженный снимок остаётся видимым.
- По умолчанию строки сортируются по PCT по убыванию. При равном значении применяется алфавитный порядок названий; порядок массива провайдера не превращается в место или тай-брейк.
- Официальный ранг, посев, серия побед/поражений, статус выхода в плей-офф и тай-брейки не синтезируются, если источник их не предоставляет.
- GB рассчитывается отдельно для конференции только при наличии 15 уникальных команд, согласованных W–L и PCT и единственного лидера PCT. Формула: `((победы лидера − победы команды) + (поражения команды − поражения лидера)) / 2`. В противном случае GB не показывается и объясняется причина.
- Домашний и гостевой рекорды, число побед в последних десяти и средняя разница очков за матч отображаются только из соответствующих полей модели. `pointsFor` и `pointsAgainst` — сезонные суммы, поэтому они не обозначаются средними значениями.
- Избранные команды хранятся в `localStorage`; фильтр и сортировка работают на клиенте.

На мобильных экранах таблица заменяется карточками, чтобы критичные показатели не требовали горизонтальной прокрутки.

## Проверка

Модели, API-ответы и интерфейс тестируются синтетическими fixture-данными. Локальную проверку можно выполнять только GET-запросом к Worker, подключённому к локальному D1. Не вызывайте `/api/revalidate`, scheduled/Cron обработчик или upstream DunkAPI для проверки этой функции.
