# PRO-202: Encyclopedia foundation

This is a manually reviewed, static reference layer. The NBA team catalog remains the canonical application identity; this directory adds Wikidata entity links and sourced city/arena facts. It does not fetch from third parties at build time or in the browser, add scheduled ingestion, or change BBS, PRO-199/PRO-200, Cloudflare, or quotas.

## Directory contract and coverage

`src/entities/nba/teamEncyclopedia.json` contains 30/30 active NBA franchise mappings to the canonical IDs in `teamCatalog.ts` and individually linked Wikidata QIDs. Every row also references stable `nba:city:*` and `nba:arena:*` subject IDs so future media can point to a shared city or venue independently of a team. City, arena, and Wikidata facts have `sourceUrl`, `asOf`, `unit`, and `nullable` fields. Entries for Chicago Bulls, Los Angeles Lakers, and Minnesota Timberwolves are the pilot examples. The Philadelphia arena uses the venue operator's current name because the NBA all-30 list still shows its former name.

The directory represents current active franchises only. Historical teams, relocations, and former venues must be separate records with their own stable identity and valid-time range; aliases must not silently merge identities. City and venue records should be reusable entities when historical coverage is added.

Coaches are volatile and should be refreshed manually or weekly after an official source check. City, venue, and historical facts are low-change and should be reviewed manually when changed or at most annually. Form and season-specific content is seasonal and belongs with sports data, not this static directory. These schedules are independent of BBS quotas and Cloudflare Cron.

## Media handling boundary

The three pilot files are cityscapes linked to canonical city subjects, rather than team logos or player portraits. The exact file pages are [Chicago](https://commons.wikimedia.org/wiki/File:Full_chicago_skyline.jpg), [Los Angeles](https://commons.wikimedia.org/wiki/File:LosAngeles_skyline.jpg), and [Minneapolis](https://commons.wikimedia.org/wiki/File:Minneapolis_Skyline_looking_south.jpg). Each was checked against its file page and `imageinfo/extmetadata` on 2026-11-19; author, title, CC BY-SA 4.0 URL, source, and modifications are recorded in `teamMediaManifest.json`. Commons reports no additional restrictions. The delivered cityscapes were visually checked; no identifiable people or readable third-party marks were observed. Commons notes that other rights may still apply, so this review does not claim to clear rights outside the photograph license.

For local copies v1 supports only exact versioned CC BY/CC BY-SA URLs in an allowlist; each image's license label must match its canonical URL, and per-file source/metadata/non-copyright review fields must be complete. CC BY-ND, unknown/All Rights Reserved, public-domain claims, and arbitrary license URLs are rejected; public-domain evidence handling is not implemented. The CC BY-SA thumbnails remain available under CC BY-SA 4.0. The reusable `MediaAttribution` component accepts only a reviewed manifest record and a same-origin `/media/...` JPEG, lazy-loads it with intrinsic dimensions, and displays a Russian fallback on failure or failed review. It renders each file's title, author, Commons source, license, and modifications. CI verifies each file is a regular JPEG under `public`, and checks its dimensions, byte count, and size limits against the manifest. The manifest caps the collection at 30 assets, dimensions at 2000 px, and files at 2 MB each. No arbitrary hotlinks, proxy, client-side external URL fetch, bulk copying, API key, or user-controlled fetch path is provided.
