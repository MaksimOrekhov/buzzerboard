# PRO-202: Encyclopedia foundation

This is a manually reviewed, static reference layer. The NBA team catalog remains the canonical application identity; this directory adds Wikidata entity links and sourced city/arena facts. It does not fetch from third parties at build time or in the browser, add scheduled ingestion, or change BBS, PRO-199/PRO-200, Cloudflare, or quotas.

## Directory contract and coverage

`src/entities/nba/teamEncyclopedia.json` contains 30/30 active NBA franchise mappings to the canonical IDs in `teamCatalog.ts` and individually linked Wikidata QIDs. City, arena, and Wikidata facts have `sourceUrl`, `asOf`, `unit`, and `nullable` fields. Entries for Chicago Bulls, Los Angeles Lakers, and Minnesota Timberwolves are the pilot examples. The Philadelphia arena uses the venue operator's current name because the NBA all-30 list still shows its former name.

The directory represents current active franchises only. Historical teams, relocations, and former venues must be separate records with their own stable identity and valid-time range; aliases must not silently merge identities. City and venue records should be reusable entities when historical coverage is added.

Coaches are volatile and should be refreshed manually or weekly after an official source check. City, venue, and historical facts are low-change and should be reviewed manually when changed or at most annually. Form and season-specific content is seasonal and belongs with sports data, not this static directory. These schedules are independent of BBS quotas and Cloudflare Cron.

## Media handling boundary

The current manifest contains zero assets. No NBA logo, player portrait, or other media has been accepted based on availability alone. Before adding an image, review the original Commons file page and its `imageinfo/extmetadata`; retain attribution and required license notices; make an optimized local copy only when that license permits it. The reusable `MediaAttribution` component accepts only an approved manifest record and a same-origin `/media/...` file, lazy-loads it, and displays a text fallback on failure. The manifest limits assets to 30, dimensions to 2000 px, and files to 2 MB each. No arbitrary hotlinks, proxy, client-side external URL fetch, bulk copying, API key, or user-controlled fetch path is provided.
