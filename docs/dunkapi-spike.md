# DunkAPI NBA spike (PRO-163)

**Проверено:** 2026-11-16

**Область:** расписание и результаты, standings, game/player box score, частота обновления, кредитный бюджет, дата NBA и локальная дата Europe/Nicosia.

**Итог:** DunkAPI — наиболее полный из изученных технический кандидат для NBA-хаба без in-game live, как для личного использования, так и для возможного публичного запуска. Проверенные ответы подтверждают пригодность выбранных сценариев MVP. Условия DunkAPI допускают показ данных в собственном продукте, но публичный запуск остаётся условным до выяснения прав на upstream-данные и NBA marks.

## Результат реального smoke-прогона

В этом отчёте фиксируются только авторизованные ответы smoke-скрипта `scripts/dunkapi-smoke.mjs`. Он выводит HTTP-статусы, размеры ответов и проверки полей, но не печатает ключ или полный payload. Неуспешные ответы не повторяются; они считаются по полной цене при соблюдении лимита.

| Проверка                                       | HTTP | Наблюдение                                                                                                                                                  |
| ---------------------------------------------- | ---: | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list_games`, NBA date 2026-11-01, season 2027 |  200 | 4 игры, все `final` со счетами; 2 из 4 начались около полуночи UTC. `date` во всех случаях совпал с Eastern date; Nicosia date была следующими сутками.     |
| `list_games`, NBA date 2026-11-15, season 2027 |  200 | 9 игр, все `final` со счетами; 5 из 9 начались около полуночи UTC. `count=9`, одна страница (`next_offset` null/не задан).                                  |
| `get_schedule`, 7 дней                         |  200 | 51 предстоящая игра; все `scheduled`, у всех обе стороны без счета. Для 39 стартов UTC попадает в 22:00–01:59; NBA date сопоставлена с Eastern date.        |
| `get_standings`, season 2027                   |  200 | 30 команд: 15 Western и 15 Eastern, 30 уникальных `team_id`; основные метрики присутствуют у всех команд. Rank-like поля в записи команды не обнаружены.    |
| `get_game`, завершённая игра с NBA date 11-01  |  200 | ID совпал с `list_games`; 2 team rows и 26 player lines. Итоговые очки обеих команд совпали с team stats; базовые player-line поля присутствуют.            |
| `get_player_games`, игрок из box score         |  200 | Вернулись 3 строки; ID игрока и базовые game-log поля присутствуют.                                                                                         |
| Дополнительный ID cross-check, NBA date 11-15  |  200 | Повторно проверены `list_games`, `get_standings`, `get_game`: ID игры совпал, обе команды box score совпали с game и standings; 24 player lines с team IDs. |

Все 9 HTTP-ответов были непустыми и успешными. Наблюдаемая задержка запросов составила 0.57–1.71 секунды от отправки до разбора JSON; это один короткий прогон, не SLA. API-ответы не дали распознанного freshness timestamp (`updated_at`, `refreshed_at`, `last_updated`, `as_of` на уровне payload).

**Кредиты:** основной прогон зарезервировал 18, дополнительный ID cross-check — 9; всего **27 из разрешённых 30** по опубликованным ценам endpoints, осталось 3. Все ответы были успешными и непустыми; account balance отдельно не запрашивался. Один ранний запуск остановился до HTTP-вызова из-за аргумента CLI и потратил 0 кредитов. Повторов API-запросов, платной подписки и пополнения не было.

## Как выполнить smoke-проверку

Ключ должен быть доступен процессу Node.js как `DUNKAPI_API_KEY`. Не помещайте его в исходники, `.env` в репозитории, fixtures, вывод терминала, GitHub или Linear. Ключ отправляется только в серверном HTTPS-заголовке `x-api-key`; скрипт не пишет его и не сохраняет ответы на диск.

```sh
pnpm run dunkapi:smoke
pnpm run dunkapi:smoke -- --execute --confirm-credit-spend=18
pnpm run dunkapi:smoke -- --verify-identifiers --execute --confirm-credit-spend=9
```

Первая команда — dry run и не обращается к сети. Вторая вручную выполняет основной набор (до 18 кредитов); третья — дополнительный cross-endpoint ID check (до 9 кредитов). Сетевые команды в рамках этого spike запускались один раз; суммарно использовано 27/30 кредитов. Лимиты 18/9 применяются **к каждому запуску отдельно**, а не к ключу или задаче целиком. Скрипт не хранит историю запросов и не проверяет остаток аккаунта; повторный запуск снова расходует кредиты и может превысить исходный бюджет PRO-163. Флаг `--confirm-credit-spend=<18|9>` требует явно подтвердить лимит конкретного режима, но не проверяет остаток аккаунта. Не повторяйте сетевой прогон с тем же ключом без отдельного бюджета. Команды не входят в CI или unit tests. Каждый режим останавливается при первой ошибке, без retries, и блокирует запросы, если верхняя оценка расходов превысит его собственный лимит.

## Покрытие по публичной документации DunkAPI

Документы DunkAPI описывают 24 basketball endpoints с REST и MCP, единым API key, кредитной тарификацией и free allowance 500 кредитов в месяц без карты. Бесплатные кредиты не накапливаются. Rate limit — 60 запросов в минуту, снижается до 10 при остатке менее 100 кредитов. Реальные ответы по выбранным endpoints получены; состав полей и глубина исторического покрытия в целом остаются ограничены выборкой и документацией.

| Возможность                          | Endpoint и цена                | Описанные поля / пробелы                                                                                                                                                                                                                                                                       |
| ------------------------------------ | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Игры по NBA date, периоду или сезону | `list_games`, 2 кредита        | `game_id`, сезон и тип сезона, `date`, `starts_at`, статус, две команды с ID/кодом/названием/счётом, периоды и overtime, площадка; есть `count` и `next_offset`. Фильтр `date` задаётся в US Eastern. В документации status filter ограничен `scheduled`/`final`, не live.                     |
| Предстоящая неделя                   | `get_schedule`, 2 кредита      | До 7 дней по умолчанию, статус `scheduled`, нулевые счёты; дополнительно медианные букмекерские линии. Отдельного in-game clock/period для live нет.                                                                                                                                           |
| Таблица                              | `get_standings`, 2 кредита     | `team_id`, `abbrev`, `display_name`, конференция, победы/поражения, home/away, очки за/против, средняя разница, последние 10, win percentage. Проверены 30 команд, 15+15, уникальные ID и наличие метрик. Rank-like поля отсутствовали; порядок ранжирования требует отдельного подтверждения. |
| Детали завершённой игры              | `get_game`, 5 кредитов         | Game/team IDs, итоговый счёт, командные и индивидуальные box-score stats (minutes, points, shooting, rebounds, assists, steals, blocks, turnovers, fouls, plus-minus), DNP, play count; также odds и win-probability поля. Не означает real-time обновления.                                   |
| История одного игрока                | `get_player_games`, 5 кредитов | ID матча, NBA date, соперник, home/result, starter/DNP и box-score line; доступна пагинация `limit`/`offset`. В рамках smoke запрашивается только несколько строк.                                                                                                                             |

**Сезон:** DunkAPI принимает год окончания сезона: `season=2027` означает 2026/27.

**Формат REST:** успешный ответ обёрнут в `data`; ошибки имеют `error` и `message`. Пагинация для `list_games` использует `limit`, `offset` и `next_offset`; проверочный запрос ограничивает ответ одним игровым днём и `limit=30`.

**Текущий live:** в реальных ответах наблюдались `final` и `scheduled`; ни один не являлся in-game live. Поставщик пишет, что scores, box scores и play-by-play обновляются примерно раз в день около 10:00 UTC; завершённые игры перепроверяются примерно полтора дня для исправления статистики. In-game live feed не предоставляется. Публичный changelog на момент чтения показывал scores/box scores «through 2026-11-14», записанные 2026-11-15 10:01 UTC, но фактический авторизованный `list_games` уже вернул 9 финальных игр за 2026-11-15. Следовательно, changelog был старее фактической выдачи; точный timestamp API response не раскрылся.

## Модель дат и часовых поясов

- Хранить `date` DunkAPI как **NBA game date в US Eastern**, а `starts_at` — как исходный UTC instant. Не переопределять NBA game date через локальную дату зрителя.
- Значение «сегодня NBA» выбирать через IANA zone `America/New_York`; отображение даты/времени для текущего пользователя строить из `starts_at` с `Europe/Nicosia`. Не прибавлять фиксированные часы: разница временно меняется вокруг раздельных переходов DST.
- При обычном совпадении сезонов разница между Nicosia и Eastern составляет 7 часов. В окнах, когда США уже перешли на DST, а Европа ещё нет (весной), либо Европа уже вернулась на стандартное время, а США ещё нет (осенью), разница 6 часов. Поэтому вечерняя игра ET часто отображается в Nicosia на следующие календарные сутки.
- Зафиксированы synthetic fixtures (не ответы DunkAPI) в `docs/fixtures/dunkapi-timezone-cases.json`; unit tests проверяют NBA date и Nicosia date на DST-границах и после полуночи UTC без API-кредитов. На реальных данных `date` совпал с Eastern date для 4 + 9 матчей и 51 предстоящей игры; вечерние матчи отображаются в Nicosia на следующий календарный день.

| UTC instant            | Eastern (NBA date)    | Europe/Nicosia        | Edge case                                          |
| ---------------------- | --------------------- | --------------------- | -------------------------------------------------- |
| `2026-03-08T23:30:00Z` | 8 марта, 19:30 EDT    | 9 марта, 01:30 EET    | США перешли на DST, Кипр ещё нет; +6 ч             |
| `2026-10-25T23:30:00Z` | 25 октября, 19:30 EDT | 26 октября, 01:30 EET | Европа уже завершила DST, США ещё нет; +6 ч        |
| `2026-11-01T23:30:00Z` | 1 ноября, 18:30 EST   | 2 ноября, 01:30 EET   | США завершили DST; +7 ч                            |
| `2026-11-16T00:30:00Z` | 15 ноября, 19:30 EST  | 16 ноября, 02:30 EET  | локальная дата зрителя уже на сутки позже NBA date |

## Полнота и проверка согласованности

Основной сценарий сделал шесть API-вызовов: два дня сезона 2026/27, следующая неделя, таблица, одна подробная завершённая игра и до трёх строк лога одного игрока. Дополнительный трёхвызовный сценарий повторно проверил cross-endpoint IDs и статистику. `list_games` вернул 4 и 9 записей, счётчик совпал с размером каждой страницы; тест с несколькими страницами не выполнялся. `get_schedule` вернул 51 `scheduled` игру с `null`-счетами. `get_standings` вернул 30 команд, 15 в каждой конференции, уникальные ID и все документированные базовые метрики. У standings не обнаружено отдельного поля ранга. В двух подробных играх `game_id`, team IDs, score и team stats совпали; строки игроков имели ID команды и базовые box-score stats. Эти проверки подтверждают структуру выбранных выборок, но не полную историческую полноту каждого сезона.

Полевые проверки выше основаны на реальных ответах, а перечисление всех возможных полей — на документации DunkAPI. Пагинация за пределами одной страницы не проверялась. Не запрашивался матч в процессе игры; документация не обещает live score/clock, поэтому этот API нельзя считать live scoreboard. Ответ standings не содержал подтверждённого rank/seed, а семантика порядка записей и tiebreakers не установлена. Не выводить официальное место из W/L или win percentage: нормализатор PRO-166 и UI PRO-172 должны сохранять ранг как отсутствующий, пока источник не предоставит подтверждённое значение или правила.

## Квоты и пригодность для MVP

При ежедневном едином серверном refresh в течение 30 дней базовый пример — `list_games` 60 кредитов + `get_standings` 60 + недельный `get_schedule` 8 = **128 кредитов**. Остаток free allowance — 372 кредита: 74 `get_game` вызова по 5 кредитов либо 186 одно-дневных `list_games` запросов по 2 кредита. Это ориентир по тарифной сетке, не прогноз по всем пользовательским сценариям; повторное использование server-side cache разделяет стоимость между посещениями, но массовые выгрузки и частые повторы нецелесообразны.

- **Личный MVP:** проверенные endpoints подходят для ежедневного расписания/итогов, standings и ограниченного числа game/player detail pages. Free-план не даёт live score; частые запросы game details и player logs быстро расходуют 500 кредитов.
- **Публичный MVP:** те же backend/cache сценарии технически применимы. Опубликованные условия DunkAPI разрешают показывать данные в собственном приложении, в том числе коммерческом, и хранить их при активном аккаунте. При этом DunkAPI не предоставляет права на NBA/командные знаки и не публикует source provenance для каждого dataset. Для public launch нужно подтвердить upstream-права и отдельно проверить использование NBA marks/images.
- **Рекомендация:** считать DunkAPI условным основным кандидатом для non-live статистического ядра: проверенные ответы покрыли выбранные MVP-сценарии и прошли cross-endpoint сверку. Это не означает полного аудита всех сезонов или юридической очистки публичного продукта. Проверенного резервного источника для полного набора игр, standings и box scores пока нет; не смешивать источники до проверки прав, статусов, идентификаторов и временной модели.
