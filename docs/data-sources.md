# NBA data sources: исследование

**Проверено:** 2026-11-16

**Область:** матчи, standings, box score, квоты, CORS и права для публичного сайта. Новостные RSS/API здесь не оценивались: для них нужен отдельный обзор условий каждого издателя.

## Решение

- **Primary и fallback не выбраны ни для приватного, ни для публичного запуска.** Требования к доступности сайта и архитектуре хранения данных ещё не закреплены, а ни один проверенный бесплатный источник не покрывает требования BuzzerBoard и допустимый режим использования одновременно.
- **DunkAPI — наиболее полный бесплатный кандидат для дальнейшего spike, но пока не выбранный primary.** По документации есть матчи/счета, расписание, standings, box scores и player lines, player game logs и play-by-play; Free включает все endpoints и разрешает хранение и показ данных в приложениях и на сайтах. Для публичного использования поставщик не предоставляет права на NBA marks и underlying third-party data; условия требуют соблюдать ограничения источников. Нужны аккаунт и API key, реальный авторизованный GET не выполнен.
- **Приватный proof-of-concept:** API Ninjas Free можно дальше оценивать только как временный источник для закрытого прототипа без хранения или кэширования Output. Документация заявляет расписание, финальные счёты по четвертям, standings и ростеры текущего сезона; `season=2026` обозначает 2026/27. Это покрытие остаётся гипотезой до авторизованного GET. Free разрешает personal/non-commercial, но запрещает передачу Output третьим лицам и его кэширование/хранение; pricing page дополнительно обозначает Free как evaluation/demo. Такой тариф несовместим с кэшем и исторической аналитикой; публичный показ на нём запрещён.
- **Приватный и публичный запуск:** DunkAPI на бумаге лучше подходит для кэширования и полного набора NBA-данных, чем API Ninjas Free; опубликованные условия DunkAPI разрешают показывать данные в своём продукте на любом плане. Но это не подтверждает права на каждую стороннюю запись, знак и изображение: конкретные upstream-источники перечислены не для каждого dataset, а действующие ограничения источников переходят к пользователю. Поэтому для public launch нужны явное подтверждение источниковых прав и smoke-test. API Ninjas Free не подходит для публичного показа и не разрешает хранение. BDL допускает downstream-показ, но его бесплатный план покрывает только часть продукта.
- **Fallback пока не определён.** API-Sports не предоставляет лицензию на публикацию; условия NBA и ESPN ограничивают использование; у TheSportsDB неполны бесплатные данные и неясно разрешение на публичный production use. Не смешивать источники без проверки прав и сопоставимости данных. Кэшировать или хранить ответы можно только если это разрешено условиями конкретного источника и тарифа.
- **Режим матча:** у API Ninjas Free для текущих матчей доступны статус, но не обновляемые счёт/часы; счёт появляется после завершения. Live score/period/clock — платная функция. Box score по игрокам не найден среди документированных endpoint'ов.
- Платные планы, пробные периоды и регистрации не использовались. Для standings/box scores на BDL или live/caching/public use на API Ninjas потребуется отдельно решить права, доступ и бюджет.

Это оценка опубликованных документов поставщиков, а не юридическое заключение. Разрешение BDL распространяется только на права, которые сам поставщик может предоставить; права на сторонние знаки, изображения и likeness отдельно не подтверждены.

### CORS

- ESPN scoreboard, standings и summary: wildcard для проверенных GET; `/teams` в GET-ответе не прислал `Access-Control-Allow-Origin`. Разные endpoints ведут себя по-разному.
- TheSportsDB v1: wildcard на проверенных GET.
- BDL: OPTIONS без ключа вернул 200; разрешил тестовый Origin `https://buzzerboard.example` (placeholder, не production domain) и заголовок `Authorization`. Авторизованный GET не проверялся.
- API Ninjas: GET без ключа вернул 400 с wildcard; OPTIONS без ключа — 200 с wildcard и разрешённым `X-Api-Key`. Это не доказывает успешный browser GET с API key или фактический доступ к данным.
- API-Sports: OPTIONS без ключа вернул 204, wildcard и разрешённый `x-apisports-key`. Авторизованный GET не проверялся.
- DunkAPI: docs описывают только авторизованный REST POST; настройки CORS не документированы. Actual preflight/POST недоступны из окружения (DNS к `mcp.dunkapi.com` не разрешился); браузерный вызов и CORS не подтверждены. API key в клиент не помещать.
- NBA CDN: 403, CORS не установлен.

CORS — только браузерное разрешение на чтение ответа, не лицензия и не гарантия стабильности. API keys следует хранить на сервере; кэшировать ответы можно только если условия выбранного источника и тарифа это разрешают.

## Оценка кредитов DunkAPI

Расчёт ориентировочный: частота вызовов UI ещё не задана, поэтому показан минимальный ежедневный refresh общего backend и отдельно полное покрытие box scores. Поставщик обновляет NBA scores, box scores и standings примерно раз в день; чаще опрашивать эти endpoints для live-матча не поможет.

| Сценарий на 30 дней сезона | Расчёт | Кредитов |
|---|---:|---:|
| Общий scoreboard/результаты | `list_games` 1 раз/день × 30 × 2 | 60 |
| Standings | `get_standings` 1 раз/день × 30 × 2 | 60 |
| Следующая неделя расписания | `get_schedule` 1 раз/неделю × 4 × 2 | 8 |
| **Базовое обновление** | 30 ежедневных вызовов матчей + standings и 4 расписания | **128** |
| Остаток free allowance | 500 − 128; по 5 credits за `get_game` | **74 box score вызова** |
| Box score всех матчей месяца | `(30 команд × 82 игры ÷ 2) ÷ 7 месяцев ≈176 игр/мес. × 5` | **≈880** |
| Базовый refresh + box score всех матчей | 128 + 880 | **≈1,008** |

Значит Free хватает на агрегированный scoreboard, ежедневные standings и ограниченное число детальных страниц. Он не покрывает box score каждого матча регулярного сезона поверх базового refresh; player logs (`5` кредитов/запрос) и play-by-play (`10`) уменьшают остаток. Это общий бюджет ключа, а не квота на пользователя. Кэширование разрешено условиями, поэтому общий серверный refresh с повторным использованием ответов — необходимая часть расчёта; фактический спрос уточнить после прототипа.
